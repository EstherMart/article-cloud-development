## O que é o S3
É o armazenamento de arquivos (objetos) da AWS. Cada PDF é um objeto dentro de um "bucket" (balde). Ele é barato e feito para arquivos grandes. O banco guarda só o caminho do PDF (`s3_key`).

Caminho: S3 > **Buckets** > **Criar bucket**.

Os nomes abaixo seguem o console em português. Entre parênteses vai o nome em inglês, caso o seu console esteja em outro idioma. Campo que não aparece aqui fica no valor padrão.

| Campo (inglês) | Valor | O que é e por quê |
|---|---|---|
| Tipo de bucket (Bucket type) | **Uso geral** (General purpose) | O tipo comum |
| Nome do bucket (Bucket name) | único no mundo, por exemplo `artigos-<seu-nome>-2026` | Ninguém no mundo pode repetir esse nome. Vai para `S3_BUCKET` |
| Região da AWS (Region) | us-east-1 | A mesma dos outros serviços |
| Propriedade de objeto (Object Ownership) | **ACLs desabilitadas (recomendado)** | Só a política manda. Evita permissões espalhadas |
| Bloquear todo o acesso público (Block all public access) | **ligado** (as 4 caixas marcadas) | O bucket fica privado. Ninguém baixa o PDF sem URL assinada |
| Versionamento de bucket (Bucket Versioning) | **Desabilitar** (Disable) | Versões antigas ocupariam espaço e cobrariam |
| Tipo de criptografia (Default encryption) | **Chaves gerenciadas pelo Amazon S3 (SSE-S3)** | Criptografa em repouso, sem custo |
| Chave do bucket (Bucket Key) | padrão | Sem ajustes |
| Bloqueio de objetos (Object Lock) | desabilitado | Impediria apagar |
| Tags | nenhuma | Opcional |

Clique em **Criar bucket**. No `.env`: `S3_BUCKET=<nome>`. Não configure CORS nem política pública: o download usa URL pré-assinada, um link temporário.

## Como o código usa o bucket (`backend/articles/services/s3.py`)
- `upload_pdf`: `upload_fileobj` com `ContentType: application/pdf`, chave `artigos/{article_id}.pdf`.
- `presigned_url`: `generate_presigned_url('get_object')`, expira em 300 s.
- `delete_pdf`: `delete_object`. O DELETE da API apaga o registro e depois o PDF; se o S3 falhar, só grava no log e sobra um objeto órfão.
- A view recusa o que não é `application/pdf` (415) e o que passa de **10 MB** (413). Falha do S3 vira 502 com mensagem fixa.

### O que pode dar errado
| Sintoma | Causa provável |
|---|---|
| Cadastro devolve 502 | `S3_BUCKET` vazio (o código usa o bucket padrão `article-cloud`, que não é seu), nome errado, região diferente de `AWS_REGION` ou LabRole sem acesso. A causa real está no log da API |
| `AccessDenied` ao abrir a URL assinada | A sessão do Learner Lab expirou (a URL nasce das credenciais temporárias) ou a URL passou de 5 minutos |
| URL assinada com erro de região (`PermanentRedirect`) | O bucket não está em `AWS_REGION` |
| Objeto sobrando depois de um erro | O POST apaga o PDF se o banco falhar, mas se o apagar também falhar fica órfão. Esvazie o bucket no fim |

## Testar no console
1. Abra o bucket > **Carregar** (Upload) > envie um PDF para a pasta `artigos/`.
2. Clique no objeto > **Object URL** e abra no navegador. Deve dar **AccessDenied**. Isso prova que o bucket é privado.
3. Clique em **Abrir** (URL pré-assinada, expira em minutos). O PDF deve abrir.
4. Pela EC2: `aws s3 cp teste.pdf s3://<bucket>/artigos/0.pdf` e `aws s3 ls s3://<bucket>/artigos/`.

## Apagar
Bucket > **Esvaziar** (digite `permanently delete`) e depois **Excluir**.

## Por que configuramos assim (estudo para a arguição)

| Configuração | Motivo |
|---|---|
| Bucket privado (Block Public Access) | O PDF não pode ser lido por qualquer pessoa com o link do bucket |
| URL pré-assinada | Dá acesso temporário a um objeto, sem tornar o bucket público e sem passar o arquivo pela API |
| Chave `artigos/{id}.pdf` | O id vem do RDS, então a chave é única e fácil de achar. Evita colisão de nomes |
| Expiração curta (300 s) | O link vazado deixa de funcionar rápido |
| Assinatura v4 | Padrão atual da AWS. Obrigatória em várias regiões |
| Validar tipo e tamanho (10 MB) na API | Evita arquivos que não são PDF e estouro de memória. O `Content-Type` vem do cliente, então não prova que o arquivo é um PDF |
| IAM Role (LabRole) | A EC2 recebe credenciais temporárias. Nenhuma chave fica no código |

Detalhe importante: no Learner Lab, a URL pré-assinada nasce de credenciais temporárias (com session token). Ela deixa de funcionar quando essas credenciais expiram, mesmo que o prazo da URL não tenha acabado.

Pergunta provável: "Como o usuário baixa o PDF sem o bucket ser público?" A API gera uma URL assinada com `generate_presigned_url`. O navegador baixa direto do S3.
